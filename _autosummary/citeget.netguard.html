citeget.netguard

citeget.netguard¶

Outbound-HTTP guard: refuse to fetch anything that is not on the public internet.

citeget fetches URLs that come from its users: the url of a reference, a page to save as Markdown, a link found inside a fetched page. When citeget runs as a hosted web app, that is a server-side request forgery (SSRF) surface: a user could ask the server to fetch http://127.0.0.1:<admin port>/ or the cloud metadata service and then download the response as a job result.

Every HTTP request citeget makes goes through get() (or a guarded_session()), which enforces a NetPolicy:

  • only http and https URLs, on the first request and on every redirect;

  • the host is resolved inside the connection step, every resolved address must be a public one, and the socket is opened to that vetted address. There is no second DNS lookup, so a rebinding DNS server cannot swap the address between the check and the connect, and every redirect hop that opens a connection is vetted the same way;

  • loopback, private (RFC 1918, fc00::/7), link-local (169.254.0.0/16, fe80::/10, which covers the usual metadata address), shared/CGNAT, unspecified, reserved and multicast addresses are refused, including when they are wrapped in IPv6 (::ffff:127.0.0.1, 6to4, NAT64, Teredo);

  • proxies and .netrc from the environment are ignored (trust_env=False) and explicit proxies are refused, so HTTP_PROXY cannot route a request around the check.

Because the check is made on the address the socket actually connects to, alternative spellings of a host (2130706433, 0x7f.1, 017700000001, a DNS name that resolves to 10.0.0.5) are all caught: they resolve to the same refused address.

The guard is on by default. A desktop user who wants citeget to fetch from their own LAN or localhost can opt out with the environment variable CITEGET_ALLOW_PRIVATE_NETWORK=1 or by passing policy=NetPolicy(allow_private=True).

>>> is_public_address("8.8.8.8")
True
>>> [is_public_address(a) for a in ("127.0.0.1", "169.254.169.254", "10.1.2.3")]
[False, False, False]
>>> [is_public_address(a) for a in ("::1", "::ffff:127.0.0.1", "fd00:ec2::254")]
[False, False, False]
>>> check_url("file:///etc/passwd")
Traceback (most recent call last):
  ...
citeget.netguard.UnsafeURLError: Refused file:///etc/passwd: scheme 'file' is not allowed (allowed: http, https)

Files the route handler streamed to disk for download navigations.

class citeget.netguard.GuardedResponse[source]¶

Bases: Response

A requests.Response that honours a NetPolicy’s ceilings.

iter_content (and so .content, which reads through it) is capped by size and by a deadline, both counted per response however many times the body is iterated; .text / .json() refuse a body over the text ceiling. Parsing .content directly bypasses the text ceiling (not the size one): citeget’s parsers all go through .text / .json().

iter_content(chunk_size=1, decode_unicode=False)[source]¶

Iterates over the response data. When stream=True is set on the request, this avoids reading the content at once into memory for large responses. The chunk size is the number of bytes it should read into memory. This is not necessarily the length of each item returned as decoding can take place.

chunk_size must be of type int or None. A value of None will function differently depending on the value of stream. stream=True will read data as it arrives in whatever size the chunks are received. If stream=False, data is returned as a single chunk.

If decode_unicode is True, content will be decoded using encoding information from the response. If no encoding information is available, bytes will be returned. This can be bypassed by manually setting encoding on the response.

Check the parts of url that can be judged without DNS; return it.

citeget.netguard.request(method, url, *, policy=None, **kwargs)[source]¶

requests.request with the destination guard. Same arguments and return.

The body is read before returning (or, with stream=True, as the caller iterates), up to policy.max_response_bytes, and the whole exchange, redirects included, must finish within policy.max_response_seconds of the call. timeout defaults to DEFAULT_TIMEOUT.

Raises UnsafeURLError if the URL, a redirect target, or an address a host resolves to is refused, or proxies= is given; ResponseTooLargeError (a subclass) if the body is over the size or time ceiling, or if .text / .json() is asked of a body over the text ceiling.

citeget.netguard.response_ceiling(limit, *, source="a caller's ceiling")[source]¶

Cap every response body fetched in this block at limit bytes.

For a caller that cannot reach each fetch’s policy= – a job spending a byte budget across strategies it does not see into. Applied wherever a policy is resolved (request(), guarded_session(), browser_route_handler()), so it only ever tightens: the policy’s own ceiling still holds when it is the smaller one. Nested blocks take the smaller limit. None or 0 adds no ceiling.

Yields the Ceiling in force. Callers in between usually swallow the refusal (a strategy that fails tries the next), so ceiling.fired is how the block’s owner learns its ceiling, not some other failure, stopped a fetch.

>>> with response_ceiling(400, source="the job budget") as ceiling:
...     capped(NetPolicy()).max_response_bytes, ceiling.fired
(400, False)
>>> capped(NetPolicy()).max_response_bytes == DEFAULT_MAX_RESPONSE_BYTES
True
